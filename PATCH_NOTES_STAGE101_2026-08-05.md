# Stage101 — удаление H1Cloud

Дата: 2026-08-05

## Что изменено

- Из добавления и редактирования узлов удалены типы **H1Cloud 3x-ui** и **H1Cloud VLESS API**.
- Из фильтров, карточек, подсказок, QR/SUB-логики и служебных подписей удалено пользовательское упоминание H1Cloud.
- Все стандартные панели теперь подключаются только как **3x-ui**. Remnawave остаётся отдельным типом.
- Установщик больше не создаёт и не переносит переменную `H1CLOUD_TLS_VERIFY`.
- Удалена отдельная документация `docs/H1CLOUD_NODES.md`.

## Автоматическая миграция базы

При первом запуске Stage101:

1. Записи с `node_type = h1cloud_3xui` автоматически меняются на `3xui`. Узел остаётся включённым, а URL, авторизация, Panel Path и Inbound ID сохраняются.
2. Записи старого `node_type = h1cloud` несовместимы со стандартным API 3x-ui. Они меняются на `3xui`, выключаются и получают статус `migration_required`.
3. Для выключенного черновика откройте **Узлы → Редактировать**, укажите URL обычной панели 3x-ui, API Token или логин/пароль, Panel Path и Inbound ID, затем включите узел.

Устаревшие столбцы SQLite и внутренний код чтения оставлены временно только для безопасного открытия и миграции существующих баз. Создать или выбрать H1Cloud через интерфейс больше нельзя.

## Перед установкой

Обязательно сохраните базу:

```bash
cd /opt/3xui-aggregator
cp data/app.db data/app.db.backup-stage101-$(date +%F-%H%M%S)
```

## Установка архива с изменёнными файлами

Распакуйте архив поверх каталога проекта, затем удалите устаревшие файлы:

```bash
cd /opt/3xui-aggregator
rm -f docs/H1CLOUD_NODES.md views/*.bak

docker compose up -d --build
docker logs --tail=200 3xui-aggregator
```

После запуска откройте раздел **Узлы** и проверьте автоматически переведённые записи.

## Проверки

Выполнены:

- `node --check app.js`;
- `node --check lib_crypto.js`;
- `node --check lib_vpn_manager.js`;
- `bash -n install.sh`;
- проверка встроенного JavaScript во всех EJS-шаблонах;
- проверка синтаксиса браузерных `<script>` в EJS;
- проверка отсутствия H1Cloud в активных пользовательских шаблонах.

Полный `npm ci` в текущей среде не запускался до конца из-за неполного внутреннего npm-зеркала; это не связано с изменённым кодом.
