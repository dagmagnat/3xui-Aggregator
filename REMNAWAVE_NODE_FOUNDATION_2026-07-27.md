# Stage 95 — Remnawave node foundation

Дата: 2026-07-27

## Что добавлено

В разделе «Узлы» появился отдельный тип `Remnawave Panel (API)`.

Для подключения сохраняются:

- корневой HTTPS URL панели Remnawave;
- API Token (Bearer), зашифрованный существующим `APP_SECRET`;
- необязательный дополнительный `X-Api-Key` для установки за Caddy Auth;
- Internal Squad UUID;
- Remnawave Node UUID;
- Host UUID.

После добавления или редактирования Aggregator выполняет безопасную проверку чтения пользователей через Remnawave API. URL нормализуется до корня панели: суффикс `/api` удаляется автоматически.

## Защитные ограничения этого этапа

Remnawave намеренно исключён из старых операций 3x-ui/H1Cloud:

- не участвует в текущем SUB/JSON Aggregator;
- не получает массовое создание, обновление или удаление клиентов;
- не участвует в маршрутизации 3x-ui;
- не запрашивается через 3x-ui inbound API;
- не создаёт локальные `client_nodes` связи.

Это предотвращает отправку несовместимых 3x-ui запросов в Remnawave.

## Как добавить

1. Открыть `Узлы → Добавить узел`.
2. Выбрать `Remnawave Panel (API)`.
3. Указать корневой URL, например `https://rw.nl.amored.ru`.
4. Вставить токен из Remnawave `API Tokens`.
5. Выбрать страну и сохранить.
6. UUID полей squad/node/host можно заполнить позднее.

При обычной установке за Nginx поле `X-Api-Key` остаётся пустым.

## Следующий этап

Отдельный Remnawave-адаптер должен реализовать:

- чтение и сопоставление пользователей;
- создание/обновление пользователя с сохранением VLESS UUID;
- назначение Internal Squad;
- включение Remnawave Host в подписку;
- массовые операции с прогрессом, безопасной отменой и повтором ошибок.
