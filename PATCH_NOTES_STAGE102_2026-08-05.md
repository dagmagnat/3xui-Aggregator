# Stage102 — мобильный импорт SUB/JSON и удаление H1Cloud

Дата: 2026-08-05

## Исправлена ошибка Happ на телефоне

Причина была в endpoint `/json/:slug`: сервер определял запрос как браузерный по `User-Agent` Safari/Chrome и вместо JSON мог вернуть HTML-страницу подключения. Мобильный Happ использует системный сетевой стек и иногда передаёт похожий `User-Agent`, поэтому приложение получало HTML и показывало ошибку невалидной JSON-конфигурации/неизвестного типа содержимого.

Изменения:

- `/json/:slug` теперь всегда возвращает `application/json`;
- HTML-страница открывается только через `/open/:slug` или `/json/:slug?view=1`;
- JSON QR в клиентах использует явный `?raw=1`;
- SUB QR использует `/sub-plain/:slug`, где выдаются только совместимые ссылки узлов без служебных строк;
- `/sub-plain/:slug` добавлен в список публичных endpoint и не требует panel access key;
- QR-коды отдаются как PNG вместо SVG для одинаковой работы Safari, WebView и Android-браузеров;
- мобильное окно QR ограничено размером экрана, коды остаются квадратными и одинаковыми.

## H1Cloud удалён

- В интерфейсе отсутствуют типы H1Cloud и их отдельные настройки.
- Старые записи `h1cloud_3xui` автоматически преобразуются в обычные `3xui` с сохранением URL, авторизации, Panel Path и Inbound ID.
- Старый отдельный H1Cloud API несовместим с обычным 3x-ui: такая запись преобразуется в выключенный черновик `3xui`, который нужно открыть и заполнить данными новой панели.
- SUB теперь доступен обычным клиентам 3x-ui и больше не зависит от наличия H1Cloud.

## Установка

Сначала сделайте резервную копию базы:

```bash
cd /opt/3xui-aggregator
cp data/app.db data/app.db.backup-stage102-$(date +%F-%H%M%S)
```

Распакуйте архив с заменой файлов, затем:

```bash
cd /opt/3xui-aggregator
bash apply-stage102-cleanup.sh
docker compose up -d --build
docker logs --tail=200 3xui-aggregator
```

На телефоне удалите ранее добавленную ошибочную подписку из Happ и добавьте её заново по новому JSON QR либо SUB QR. В браузере панели выполните жёсткое обновление страницы.

## Быстрая проверка endpoint

Подставьте slug клиента:

```bash
curl -i 'https://ВАШ-ДОМЕН/json/SLUG?raw=1'
curl -i 'https://ВАШ-ДОМЕН/sub-plain/SLUG'
```

Ожидается:

- JSON: `HTTP 200` и `Content-Type: application/json`;
- SUB: `HTTP 200` и `Content-Type: text/plain`;
- в начале JSON не должно быть `<!DOCTYPE html>`.
