# Безопасная синхронизация и отмена — 2026-07-24

## Найденные причины

1. `Импорт и синхронизация` после чтения источника автоматически проходил по **всем активным узлам**. Выбора целевых серверов не было.
2. Закрытие страницы или переход назад не отменяли серверный цикл. Node.js продолжал последовательно создавать/обновлять клиентов.
3. Недоступный узел проверялся заново для каждого клиента. При тайм-ауте 8 секунд и 57 клиентах это могло добавить примерно 456 секунд ожидания только на один сервер.
4. Новый Clients API 3x-ui обновляет клиента по email, но старый вызов агрегатора передавал UUID. Из-за этого появлялось сообщение `3x-ui не вернул полную запись клиента ...` и защищённое обновление отменялось.
5. При обновлении существующей связи агрегатор менял локальную запись до подтверждения 3x-ui. При timeout локальная подписка могла расходиться с фактическим состоянием узла.

## Что изменено

- Импорт по умолчанию теперь работает **только локально** и не меняет удалённые узлы.
- Для удалённой синхронизации нужно явно выбрать конкретные целевые узлы.
- Узел-источник автоматически исключается из списка целей.
- Кнопка `Обновить клиентов узлов` также требует явного выбора серверов.
- Перед массовой операцией каждый выбранный узел проверяется один раз. Недоступный сервер полностью пропускается.
- Если узел теряет связь уже во время работы, после двух сетевых ошибок подряд он исключается из текущей операции, чтобы не ждать тайм-аут для каждого оставшегося клиента.
- На странице выполнения добавлена кнопка `Безопасная отмена`.
- Отмена останавливает процесс после текущего запроса и показывает фактически обработанное количество.
- Исправлен поиск полной записи клиента по email/UUID для актуального 3x-ui.
- Локальная связь обновляется только после успешного ответа удалённой панели.
- На мобильном экране длинные ошибки ограничены по высоте и прокручиваются.

## Важное ограничение отмены

Отмена не откатывает уже успешно выполненные изменения. Она гарантирует, что после текущего запроса новые клиенты и узлы больше не обрабатываются. Результат показывает точку остановки, например `50 из 100`.

## Что делать с уже запущенной старой операцией

Старая версия не имеет канала отмены. Чтобы немедленно прекратить её цикл, перезапустите контейнер/процесс агрегатора. Уже отправленный в 3x-ui текущий запрос может завершиться, но следующие клиенты обрабатываться не будут.

После перезапуска:

1. Проверьте доступность каждого узла из раздела `Узлы`.
2. Не запускайте синхронизацию на всех серверах.
3. Выберите только нужный узел и доведите частичную синхронизацию до конца.
4. Проверьте у проблемного клиента UUID, email, `enable`, `expiryTime`, `totalGB`, `flow` и наличие привязки к inbound в оригинальной 3x-ui.
