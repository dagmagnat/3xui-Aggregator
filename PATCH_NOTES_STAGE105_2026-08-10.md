# Nexus Panel 1.0.1 — восстановление входа по secret-key

Дата: 2026-08-10

## Симптом

Ссылка вида `/login?key=...`, показанная установщиком или диагностикой, могла
отвечать простым текстом `Not found` даже с корректным ключом из `.env`.

## Причина

Установщик печатал `PANEL_ACCESS_KEY` из `.env`, а сервер сверял запрос с
зашифрованным `panel_access_key` из SQLite. После восстановления старой базы,
переноса установки или ротации переменных эти значения могли различаться.

## Исправление

- Новый ключ текущего окружения распознаётся как одноразовый ключ восстановления.
- После успешной проверки он сохраняется в SQLite и дальше используется как
  обычный основной ключ.
- В базе хранится только SHA-256-отпечаток состояния окружения, не сам запасной
  ключ.
- Если администратор меняет ключ в авторизованных настройках, старый ключ из
  `.env` больше не принимается как постоянный fallback.
- При следующей явной ротации `PANEL_ACCESS_KEY` новое значение снова получает
  одноразовое право на восстановление.
- Установщик и пункт «Диагностика и восстановление доступа» читают фактический
  runtime-ключ из SQLite внутри контейнера.

## Проверка

```bash
npm run check
npm run test:panel-access
```
